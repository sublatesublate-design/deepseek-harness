# Agent Note：有界项目记忆与受控 Git 工作流

状态：已实现

[English](2026-08-14-bounded-project-memory-and-git-workflow.md) | 中文

## 问题

通用 Shell 可以运行 Git，但它没有为模型提供窄而明确的工作流约定，也无法区分仓库观察与持久提交。项目指令可以保存稳定规则，但若把它当作不断增长的任务日记，会持续占用请求上下文，并把必须遵守的权威内容与可能出错的召回内容混在一起。

## 决策

**Git 使用小型原生工作流界面。** 标准、代码和 Cordis 预设提供状态、受限差异、明确路径的暂存或取消暂存，以及仅提交现有暂存区的工具。Git 通过 subprocess seam 以固定参数向量和受限收集输出运行。该界面不提供远程修改或历史重写操作。

**每次提交都必须重新审批。** Git 插件对每个 `git_commit` 调用从 `tools/pre-execute` 返回 `ask`。审批只覆盖一个明确调用；允许编辑或暂存文件并不等于允许创建仓库历史。

**项目记忆与指令、会话压缩分离。** 生成状态保存在 Git 根目录的 `.dsh-project-memory.json`，仓库外则保存在会话目录。常规文件检查会拒绝符号链接。读取时校验完整 schema 和配置上限；写入经过共享的 `fs/write-intent` 门禁，并按版本比较后发布。团队自行决定提交还是忽略该文件。

**自动进入上下文的只有受限索引。** 会话第一个有效步骤只得到活动条目的 id、类型、标题和标签。正文保留在磁盘，直到 `memory_search` 或 `memory_read` 检索到相关内容。搜索结果数、摘要、单条长度、存储总量和启动索引均设硬上限。更新替换明确 id，归档则保留被取代内容的历史。

## 考虑过的替代方案

**每次请求注入完整记忆文件。** 否决，因为成本和注意力占用会随存储增长，无关条目会与当前任务竞争；提示词缓存即使节省费用，也无法恢复上下文容量。

**把项目记忆写进 `AGENTS.md`。** 否决，因为强制指令与辅助召回具有不同的权威性和保留规则。必须始终生效的规则仍以 `AGENTS.md` 为准。

**立即加入嵌入和向量数据库。** 暂缓，因为严格限量的本地存储配合词法检索可检查、可移植，足以先固定生命周期。以后可替换搜索实现，而不改变指令与记忆的边界。

## 结果

编码智能体无需首先使用不受限 Shell，就能检查并准备仓库变更；用户仍掌握独立的提交边界。跨会话项目知识可以保留，同时不会让整个存储永久占用提示词。记忆仍是可能出错的生成状态：不得保存秘密，不能覆盖已提交的指令，并应在事实变化后更新或归档。
