# Agent Note：可选插件激活的显式故障隔离

Status: implemented

[English](2026-08-14-contained-plugin-activation.md) | 中文

## 问题

Loader 有意将一次组合更新视为事务，这对必要服务是正确的，但也意味着一个实验性或第三方插件可以阻止原本可用的应用启动。若静默放宽所有行，则会掩盖核心服务缺失，并让只完成部分初始化的进程表面上显得健康。

## 决策

**隔离必须在组合边界显式声明。** 基础 profile 挂载一个 `pluginFaults` 注册表；只有 Loader 行使用 `@deepseek-ai/dsh-plugin-fault-boundary/boundary`，并在 `config.plugin` 指定目标时，插件才选择隔离。普通行继续保持 Loader 的明确失败行为。

**包装器持有一个子 Fiber。** 它通过所属 Loader 树解析目标，在包装器下挂载目标，并捕获导入或激活失败。失败的子 Fiber 会被处置，而包装器保持 active，使同级行仍可停稳。重试会串行执行，处置既有子 Fiber，再重复相同的导入与激活路径。

**诊断受限，恢复范围窄。** Host 日志接收失败上下文。注册表暴露最长 500 字符的单行消息、生命周期阶段与是否可重试。插件清单 Remote 投影目标而非包装器，并且只允许重试当前失败且仍存活的边界。Web 设置行展示该状态，但不暴露传输错误。

**插件仍是受信任的本机代码。** 插件共享 Harness 进程的文件系统、网络、环境变量、原生模块与进程控制权限。“插件”设置页面会在清单前说明这一规则。子 Fiber 是生命周期故障边界，不是能力或安全边界。

## 曾考虑的替代方案

**让所有 Loader 行都尽力而为。** 不采用：必要服务及其依赖方会继续等待或在稍后失败，反而掩盖第一个可操作的启动错误。

**修改 vendored Loader 事务。** 不采用：隔离属于产品策略，而非通用 Loader 语义；显式包装器可以保持 vendored 生命周期约定不变。

**把子 Fiber 当成沙箱。** 不采用：Fiber 管理生命周期所有权，但不限制 Node.js 权限；把它描述成隔离会制造虚假的安全边界。

**在独立进程中运行每个插件。** 当前架构不采用：Cordis 插件共享进程内服务与 context。真正的进程边界需要服务协议、显式能力、序列化规则、资源限制与监管机制，它会形成独立的插件 runtime，而不是此激活包装器的简单扩展。

## 后果

可选插件失败时不会拖垮应用，用户可在现有“插件”设置页面检查并重试。核心组合仍保持严格。部署假定插件代码及其更新来源可信。死循环、原生崩溃、进程退出、故意滥用 Host 权限，以及激活后任意未处理的异步失败仍不在边界保证内。
