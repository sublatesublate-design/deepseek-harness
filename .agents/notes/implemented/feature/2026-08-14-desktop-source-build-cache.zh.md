# Agent Note: 桌面端源码构建缓存

Status: implemented

[English](2026-08-14-desktop-source-build-cache.md) | 中文

## 问题

桌面端源码入口不能把当前源码与过期的忽略构建产物混在一起，但每次启动前重新构建所有工作区 package 会刷满终端，并让未变更的启动承担完整构建成本。仅凭文件修改时间无法判断 Git checkout、生成的 Client bundle 或复制的 Web 资源是否新鲜。

## 决策

**启动器计算明确运行时输入集合的指纹。** `apps/desktop/scripts/start.mjs` 会对根构建配置、CLI、Desktop、Web、package 源码、原生源码和 vendored runtime 的 Git 索引条目进行哈希，再加入每个脏文件或未跟踪输入的内容。因此，即使文件已经处于修改状态，继续编辑仍会改变指纹。集合之外的文档和测试不会触发运行时构建。

**快速启动同时要求状态匹配和产物哨兵存在。** `.cache/deepseek-desktop/build-state.json` 记录带版本号的成功构建指纹。当状态缺失或无效、指纹不同，或者 CLI、Electron、Web、Client connection 哨兵缺失时，启动器会重新构建。算法或输入集合发生变化时需要递增状态版本。无法读取 Git 状态属于启动失败，不能据此复用来源未知的产物。

**只有输入稳定的成功构建才更新状态。** 启动器运行既有 `build:desktop` 组合，并把输出重定向到 `.cache/deepseek-desktop/build.log`。仅当构建以零退出且构建后指纹未变化时才记录状态；构建期间源码变化会再次构建，最多尝试三次。失败时显示最近输出和完整日志路径；成功构建和快速启动只显示简短状态。

**Electron 启动不再经过另一层 package manager。** 准备完成后，启动器解析工作区 Electron 可执行文件并直接启动。普通的未变更启动因此不会显示 package manager 配置和可选平台警告。`pnpm run build:desktop` 仍是显式全量构建命令，其本身不声明缓存已经新鲜。

## 曾考虑的替代方案

**每次启动前重新构建。** 不采用：这种方式正确，但会拖慢未变更启动，并输出数千行与操作桌面应用无关的信息。

**比较修改时间。** 不采用：checkout 操作可能保留或重排时间，生成产物存在多个所有者，而且不同文件系统的时钟粒度不同。

**仅检查 Electron 入口是否存在。** 不采用：Electron 本身为最新时，CLI、Web 资源或生成的 Client 半面仍可能过期。

## 后果

未变更启动只需读取 Git 元数据并对脏文件内容进行哈希，随后以一行启动器状态启动 Electron。相关源码编辑和哨兵缺失仍会承担完整构建成本。维护者必须把新的运行时源码根和关键产物所有者加入输入与哨兵列表；这些规则变化时通过状态版本使旧判断失效。缓存是可随时删除的忽略数据，不能替代发布或 CI 构建。
