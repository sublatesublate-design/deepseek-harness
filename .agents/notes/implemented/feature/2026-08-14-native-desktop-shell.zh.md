# Agent Note: 基于 Web profile 的原生桌面外壳

Status: implemented

[English](2026-08-14-native-desktop-shell.md) | 中文

## 问题

浏览器应用已经持有完整的用户工作流，但从终端启动后，窗口生命周期、聚焦、桌面框架和外部链接行为都交给了通用浏览器。桌面应用需要原生窗口行为，同时不能创建另一套可能偏离插件组合 Web profile 的渲染器。

## 决策

**桌面应用包装已发布的 Web profile。** `apps/desktop` 将工作区 CLI 解析为应用依赖，通过 Electron 内置 Node 模式在桌面专用的 3081 端口启动回环 `dsh web` 进程，然后在单个 Electron `BrowserWindow` 中加载。这条进程路径同时适用于 Windows 与 macOS，无需按平台选择 `node.exe` 或 `node`。托管默认值与浏览器命令的 3080 端口分离，防止意外复用另一个已安装版本。`DSH_DESKTOP_URL` 选择显式管理的本地开发服务，`DSH_DESKTOP_PORT` 更改托管端口。根级 `pnpm desktop` 入口遵循[桌面端源码构建缓存](2026-08-14-desktop-source-build-cache.md)，因此快速启动仍会拒绝过期或不完整的忽略产物。

**托管 API 要求每进程随机凭据。** 桌面进程生成 256 位随机数，通过 `DSH_CONTROL_TOKEN` 将令牌传给 Host，并把 `x-dsh-control-token` 注入窗口的 HTTP 请求与 WebSocket 握手。令牌不会进入渲染器 URL 或应用启动数据，其凭据形环境变量名会被共享清理器从 agent 子进程环境中移除。就绪探测要求 `/api/auth-probe` 在携带凭据时成功、匿名时返回 401，因此不会接管已占用 3081 的未认证进程。未配置令牌的普通 `dsh web` 保持兼容；显式 `DSH_DESKTOP_URL` 可与 `DSH_DESKTOP_CONTROL_TOKEN` 配对。

**Web 渲染器通过 URL 状态选择桌面框架。** Electron 窗口加载 `?desktop=1&platform=<platform>`。仅在该模式下，Web 入口挂载一个固定拖动区域，并按其高度缩减应用根节点。普通浏览器 URL 保持既有的全高布局与 DOM。

**原生进程持有原生策略。** 渲染器使用上下文隔离和 Chromium 沙箱，禁用 Node integration。新窗口在操作系统浏览器中打开，页面权限请求被拒绝，一个进程持有应用实例，常规窗口尺寸保存在 Electron 的用户数据目录中。当保存坐标与当前显示器相交的有效区域不足时，桌面端会丢弃该坐标。源码启动器在 Windows 上保持 Electron GUI 进程可见，同时隐藏构建与服务控制台。启动导航、应用页面导航和第二实例激活都会恢复并显示原生窗口。Windows 使用稳定的应用 ID 与标题栏 overlay；macOS 使用内嵌红黄绿按钮、标准应用菜单、Dock 激活行为与 Dock 图标。

**启动状态留在原生窗口内。** Host 就绪等待开始前，窗口会加载本地化进度文档，并在故障期间保持可见。就绪探测会区分连接拒绝、HTTP 故障、非预期文档、认证接口缺失、凭据被拒绝和匿名访问未受限制。启动失败会渲染一份经过转义的恢复文档，展示简明诊断、默认折叠的长度受限输出、持久日志路径，以及重试自有服务或在文件管理器中显示日志的操作。活动日志仅在取得单实例锁后轮换并保留上一次运行，因此被拒绝的第二次启动不会清空所有者的诊断。

**源码启动器只持有其创建的进程，并等待系统静止。** 重试和应用退出会先移除输出监听器，在 Windows 终止完整的自有进程树，在其他平台从 `SIGTERM` 升级到 `SIGKILL`，并等待子进程关闭后再重新绑定或完成退出。显式配置的开发 URL 仍由外部持有。构建产物冒烟测试会使用隔离的临时用户数据启动真实 Electron、CLI、认证 API 和 Web 路径，再验证退出后临时端口已经释放且测试数据已经删除。

## 曾考虑的替代方案

**构建第二套 React 桌面渲染器。** 不采用：会话、设置、工具、审批、工作区和插件提供的 UI 都需要重复集成，并可能偏离浏览器行为。

**通过 `file://` 加载 Web 构建产物。** 不采用：浏览器应用依赖 Host API 和运行时注入的启动清单，只有静态文件无法提供可用的 Harness 会话。

**要求用户手动启动 `dsh web`。** 不采用：原生启动器应持有可用的冷启动路径。显式开发 URL 仍可保留，而无需削弱经认证的托管默认值。

**依赖时间戳或不完整的变更文件列表。** 不采用：CLI、两个编译面、生成的客户端 bundle、Web 资源和 Electron 入口共同构成一套可运行产物。[桌面端源码构建缓存](2026-08-14-desktop-source-build-cache.md)改为根据 Git blob id 和脏文件内容计算明确运行时输入集合的指纹，检查产物哨兵，并在无法确认新鲜度时拒绝快速启动。

**信任回环地址上的所有进程。** 不采用：模型控制的 shell 或无关的同用户进程可以直接调用 Host API。每进程随机认证使“持有桌面凭据”与“网络可达”成为两件不同的事。

**允许 Electron 渲染器访问 Node.js。** 不采用：页面已经通过仅限回环的 Host API 访问特权操作。Node integration 会建立第二条更宽的权限路径。

## 后果

桌面应用与浏览器应用共用同一套产品实现，Electron 增加平台感知的原生框架、显示器安全的窗口尺寸记忆、单实例聚焦、受控外部导航、经认证的本地控制面、结构化启动恢复，以及持续到关闭完成的进程树所有权。仅当已记录的输入要求重新构建时，源码启动才付出完整相关构建成本。启动器支持 Windows 与 macOS，并需要 Node.js 工具链。产品引导、自动更新、签名和可分发安装包属于后续独立的发布工作。
